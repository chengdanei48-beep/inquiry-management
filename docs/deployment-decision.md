## 構成の選択(最小の費用・最小の手順)

| 案 | 内容 | 判断 |
|---|---|---|
| **EC2 1 台(採用)** | Node.js 24 と SQLite を、そのまま載せる。SQLite のファイルは、サーバーのディスクに置く | 構成が単純で、費用が小さく、学習範囲(EC2・セキュリティグループ)に合う |
| Lightsail | 月額固定の簡易サーバー | 設定は簡単だが、AWS の基本サービスの理解を示しにくい |
| App Runner・ECS(コンテナ) | Docker で実行 | SQLite のデータが再起動で消えやすく、構成が重い。この課題には過剰 |
| Lambda + API Gateway | サーバーレス | SQLite のファイルを置けない。DB の作り直しが必要 |
| EC2 + RDS(PostgreSQL) | 本格的な構成 | 費用が増える。課題の指示で PostgreSQL は不採用 |

## デプロイのために、変更したこと(v1.1.0)

| 項目 | 変更前 | 変更後 |
|---|---|---|
| 待ち受けアドレス | `127.0.0.1` 固定 | 環境変数 `HOST`。既定は `127.0.0.1` のまま |
| 認証 | なし | 環境変数 `APP_PASSWORD` を設定すると、全ての画面・API に Basic 認証。**localhost 以外で待ち受けるときは、パスワードが無ければ起動しない**(認証なしで公開する事故の防止) |
| Host ヘッダーの検査 | localhost のみ | 既定は localhost のみ。`ALLOWED_HOSTS` で、外部の Host 名を許可 |
| ヘルスチェック | なし | `/healthz`(認証なし。内容は固定) |
| 常駐化 | なし | systemd(`deploy/inquiry-management.service`)。root では動かさない |
| セットアップ | 手作業 | `deploy/setup-ec2.sh`(EC2 の「ユーザーデータ」から実行) |

localhost での利用(`npm start`)は、これまでと同じ。**既定の動作は変えていない**(既存の 265 件のテストが、変更なしで通ることで確認)。

## 本番で必要な対策(課題の範囲では、行っていない)

| 項目 | 内容 |
|---|---|
| HTTPS | Basic 認証のパスワードが、暗号化されずに流れる。ロードバランサー・CloudFront と、証明書が必要 |
| 総当たり対策 | パスワードの試行回数の制限がない。12 文字以上の長いパスワードで、リスクを下げている |
| バックアップ | 自動バックアップはない。サーバーを削除すると、データは失われる(サンプルデータのため、問題ない) |
| ユーザーごとの認証 | 共通のパスワード 1 つ。「操作する担当者」は選ぶだけ |
| 実データ | **入れない**。個人情報を扱うなら、上の全てが必要 |
| 複数台・スケール | SQLite は 1 プロセス前提 |

## コンテナ化について

引き続き、行っていない。EC2 に直接配置する方が、手順が少なく、課題の範囲に合う。コンテナ化を検討する場面と、必要な変更は次のとおり。

- 利用する環境に Node.js 24 を入れられない、など、環境差をなくしたいとき
- 必要な変更: `HOST`・`APP_PASSWORD` を環境変数で渡す(**実装済み**)、`data/` をボリュームにする、`node:24-slim` を基にした Dockerfile を用意する

## 注意

- 認証なしで、外部へ公開しない(起動時に拒否される)。
- AWS のアクセスキー・パスワードを、リポジトリに入れない。
- 評価の後は、インスタンスを削除する(費用の発生を止める)。
